# Copilot Fusion 発表メモ

## Fusion とアーキテクチャ

Fusion は単一モデルではなく、タスクに応じてモデルと Single、Cascade、Critique の実行方式を選ぶシステムです。利用者は effort を選びます。必要ならモデルを追加で呼びますが、Highでも毎回複数モデルが動くわけではありません。

図の緑は今回 SDK イベントで観測した工程です。Single はルーティングとコミットの間に1つの primary がありました。Cascade は judge が accept し primary が最終ソース、Critique は draft、critic、条件付き revision が動き、revision が最終ソースでした。DB や RAG、judge の判定基準は分かりません。失敗時のフォールバックは公開 Issue と SDK の型にありますが、今回は再現していません。CLI の subagent は別の機能です。

キャッシュの比較では、同じ長い依頼を同一会話で繰り返した2ターン目に、両回とも約1.08万トークンの読み取りが報告されました。別セッションでも 1,271 トークンが読み取られました。会話履歴やモデルが同時に変わるため、差の原因までは断定できません。

HyDRA 論文は関連するモデル選択の研究です。図は論文の Figure 1 そのものです。0〜1の数字は推定された能力要求で、実際の測定した処理時間や精度ではありません。論文の例は WebSocket 再接続の競合修正です。この論文だけで現在の Fusion の全内部実装を断定できません。

同一のJavaScript修正課題をSDKで20回実行すると、すべてCascadeで、primaryの gpt-6.1-sol と judgeの gpt-6-luna が完了しました。repairの開始イベントはありませんでした。これは実行された工程の観測で、選択の理由や評価基準を示すものではありません。

## コマンドとデモ

基本の /model、/usage、/context に加え、/fleet は並列の委任、/env は読み込まれた指示やagentの確認、/rubber-duck は別の視点からの批評に使えます。/fleet は CLI の機能で、Fusion の Critique と同一ではありません。実験で使ったのは CLI の --fleet で、/rubber-duck の実行は未確認です。

録画は2026年11月26日にCopilot CLIを直接起動し、Fusion Highに質問したものです。待ち時間は短縮しています。静かな出力のため録画にはモデルや経路が表示されません。経路を調べる場合は別途SDKの予定、開始、完了イベントを照合します。

Framekitの画像は別の実開発試行で、修正前後のローカル初期フレームを比較しています。デプロイ済みの画面ではありません。

## 実験とTips

subagentの例では、画面の共通依頼に委任を明示した一文を加えました。ほかにAGENTS.mdの指示とCLIの--fleetも同じファイル調査で比較しています。グラフは開始または完了イベントが少なくとも1件あったセッションの数です。条件ごとの結果や小さな試行数を確認し、一般的な呼び出し率とは扱いません。

見直し指示の比較は各10回。基本依頼と、3ケースを1回見直す依頼を交互に実行しました。中央値は約10.1秒と10.7秒です。これは一つの短い課題での結果で、差の因果関係は分かりません。ツールを無効にしているため、エージェントのツール実行ループや、見えない内部推論回数は測れていません。

20件の生成コードはすべて同じ修正でした。コードを抽出して、0、undefined、null、2500の4ケースをこちらで実行し、80件すべて通過しました。モデル自身がテストを実行したという意味ではありません。

コストの例では、同じIssue本文を与えてHigh優先とMax単独を各1回比較しました。Highのテスト案は図を含めましたが、Maxの案は図の文字が対象から漏れていました。利用量は34.426と30.113 AI creditsです。テスト案は実行しておらず、同じ品質ではないため単純な費用比較はできません。AI creditsは請求額そのものではありません。

# 発表原稿の下書き：Copilot Fusion

登壇時間・対象者は未確定。内容と尺は調整する。

## 1. タイトル

今日は GitHub Copilot Fusion がモデルと処理の流れをどう選ぶかを、実際に動かして見てみます。

## 2. 問題意識

コーディングでは、速く答えてほしい質問もあれば、設計を丁寧に確認したい課題もあります。どのモデルを選ぶかを毎回判断するのは簡単ではありません。

## 3. Fusion とは

Fusion は、リクエストに応じてモデルを選び、必要に応じて複数の工程を組み合わせます。以前 HydraFusion と呼ばれていた研究プレビューの技術を含みます。

## 4. 3つの方式

Single は一つのモデルで答えます。Cascade は最初の回答を判定し、必要なら別の工程に進みます。Critique は回答をレビューして修正につなげます。毎回同じ方法になるとは限りません。

## 5. ライブデモ

決済 API のリトライ設計を依頼します。画面に表示された処理方式、実際に開始・完了した工程、モデル名、回答を見てください。

## 6. 実行結果の読み方

予定に表示された工程と、実際に受信した開始・完了イベントは区別します。表示されていない内部処理を推測することはできません。

## 7. 利用時の注意

Fusion が使うモデルにはそれぞれ利用枠や料金が適用されます。利用可能なモデルはプランや組織ポリシーにも依存します。結果はリクエストごとに変わります。

## 8. まとめ

Fusion にモデルと方式を選んでもらい、実際に観察できる工程と最終回答を確認できます。

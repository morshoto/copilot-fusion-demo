# Fusion runtime 調査：事前プロトコル

2026-11-26 に計測を開始。目的は公開イベントから観測可能な経路・工程・キャッシュを調べること。内部実装の網羅を主張しない。Copilot SDK 2.0.1、Fusion High を基準、Critique を得る場合に Max も使用。ツール・ホスト Git 操作は無効、合成テキストのみ。新規セッションと継続ターンの送信開始〜完了を測定する。指示とプロトコルは実施前に記録する。

## 仮説と対照

1. **キャッシュ**: 長い同一接頭辞の連続ターンと、新規セッションで同一接頭辞を送る場合を比べる。変更課題は同一接頭辞を維持し末尾の依頼のみ変更。どちらでも同じ値になる、モデル切替・送信内容・時間・サーバ負荷などが影響する、フィールド自体が無い可能性を対立仮説とする。セッション内の会話履歴は増えるため厳密な同一入力比較ではない。
2. **経路と工程**: 単純な回答と複雑な設計レビュー、High と Max で観測された方式・予定・開始・完了・verdict・最終ソースを比較する。複雑さによりCritiqueが必ず選ばれるとは想定しない。repair・failureなどは自然に現れた場合のみ観測し、強制障害や権限変更は行わない。
3. **Single の前後**: route_started、resolved、各モデル工程、usage、completed の受信順を記録する。モデル工程以外の内部呼び出し・ルーティング用の推論・外部DBの有無は公開イベントだけでは証明できない。

フェーズごとの requestCount / cachedTokens / cacheWriteTokens とターン合計を混算せず保存。欠損は null、0は明示値として区別。回答本文・中間草案・handoff内容・session/turn/phaseの実IDは公開しない。イベントの匿名フェーズIDは同一ターンの照合にだけ使う。各試行の利用量はAI credits報告値（請求額ではない）で保存。時間・値の違いの因果関係は主張しない。

追加追試: 既存の条件をもう一組実行して偶然の数値と混同しない。複雑な設計課題をHighでも試し、同じ課題のMax試行と方式を比較する。複雑さやeffort単独の因果効果は結論しない。

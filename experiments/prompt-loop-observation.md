# プロンプトと実行ループの観測

2026-11-25 に [subagent 実験](subagent-observation.md) の2試行を使い、プロンプトの違いと観測可能な実行時間・回数を記録した。Framekit の同じ固定 SHA、同じ読み取り専用の hero 調査で、A は委任を指定せず、B は subagent への委任と結果の取り込みを要求した。B のみ `task` を許可したため、プロンプトだけを変えた対照実験ではない。

## 数え方

- **経過時間**: 各 JSONL の `session.start` から最後の `result` まで。CLI 起動前の時間は含まない。
- **モデル呼び出し開始数**: JSONL の `model.call_start` 件数。親・subagent・Fusion 工程の区別をせず数える観測可能なイベント数で、隠れたモデル呼び出しや利用請求数を表さない。
- **ツール開始数**: `tool.execution_start` 件数。親と subagent を合わせる。成功回数ではなく、繰り返しや失敗も含む。
- **subagent 開始数**: `subagent.started` 件数。Fusion の批評工程とは別に数える。

これらは利用可能なイベントを数える実用的な定義で、「エージェント内部の実行ループ全体」を完全に把握したという意味ではない。時刻とイベントは同じ CLI バージョンで取得した。

## 発表に使う知見と限界

- **観測:** 明示的な委任を含む B では、subagent 開始・完了をイベントで確認できた。A では開始イベントはなかった。
- **使い方:** 実行ループを比較する前に、どのイベントを数え、時間の始点と終点をどこに置くか決める。最終回答だけでは委任や途中工程を数えられない。
- **解釈の限界:** B は短時間だったが、Fusion のパターンとモデル、`task` 権限が異なる。キャッシュやサービス負荷も統制せず、各1回だけなので、委任指示が高速化した、あるいは回数を増減したとは言えない。別試行で指示のみを変え、同じ環境・許可で反復し、モデルと経路の差を併記する必要がある。
- **自律実行の使いどころ:** 読み取り専用の分割可能な調査なら委任の成否を安全に観察できる。実際の修正や自律ループの品質はこの試行では未確認。ループ数・時間だけで品質を判定しない。

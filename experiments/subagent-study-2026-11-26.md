# subagentへの明示的な委任を繰り返し観測

## 方法

Copilot CLI 1.0.115、Fusion High（`--model auto --auto-tier hydrafusion`）。隔離した一時ディレクトリにある1ファイルの `timeoutMs(value)` に、0を誤って5000として扱うバグを入れ、原因と修正案を依頼した。`view` と `task` のみを両条件で同じように許可し、書き込みと外部アクセスを指示で禁止。組み込みMCPとカスタム指示は無効にした。委任を指定しない文と、その末尾に「subagentにファイルの調査を委任してください。」を追加した文を交互に並べ、各5回ずつ実行した。各ペアは2セッションが同時実行されている。

親セッションに通知された `subagent.started` と `subagent.completed`、CLIプロセス開始から終了までの時間を数えた。個別結果とプロンプトは [公開用データ](data/subagent-study-2026-11-26.json) に記録した。ログ本文やセッションIDは含まない。

| 条件 | 開始・完了 | 経過時間の中央値 |
|---|---:|---:|
| 委任指定なし | 0/5 | 14.8秒 |
| 委任を明示 | 5/5 | 40.7秒 |

この5組では上記のとおりだったが、単一の小さな課題であり、実際の開発タスクの呼び出し率を示さない。負荷、キャッシュ、内部経路、モデル側の非決定性は統制されていない。子エージェントの全利用量・品質を独立評価したものでもない。`aiCredits` は親セッションのFusion完了イベントで得た値で、請求額でも、子セッションを含む総額の保証でもない。

AGENTS.md と `--fleet` の観測は [別のFramekit実験](subagent-observation.md) で各1回実施したもので、この5組と混ぜて比較しない。

## 再実行

```sh
node experiments/subagent-study.mjs /path/to/copilot /tmp/subagent-study.json
```

各条件5回、計10回の実リクエストでCopilotの利用量が発生する。読み取り専用の一時ファイルを作る。実行前にCLIのバージョンと権限を確認する。

# Framekit を使う Fusion 実験の準備

## 題材

候補は [Framekit #796: landing hero の初期表示時の可読性](https://github.com/morshoto/framekit/issues/796)。headless や Final Cut の操作を必要とせず、変更前後を画面で説明できる。調査時点（2026-11-25）の Issue は open、対応する open PR は検索で見つかっていない。実験前に Issue、PR、並行作業とベース SHA を再確認し、着手済みなら別の未着手課題を選ぶ。調査時の `main` は `fc51a634a80c4aea363d8eb34b9c1794d371853e`。これは実行時の固定値ではない。

課題の成功条件は Issue 本文に従う。ファーストペイントからヒーローのテキストと CTA が読め、light/dark の両テーマで表示を確認する。アクセシビリティ、動きの抑制、画面幅、既存のリンク動作を確認し、実際のブラウザで最初の数秒を観察する。自動テストの成否だけを視覚的な受け入れ結果にしない。Framekit の紹介ではなく、Fusion への依頼、実行の観測、検証を発表の主題にする。

## 実行方法

1. Framekit の最新状態と Issue、他の PR/worktree を確認し、同一ベース SHA から試行ごとに独立した一時 worktree を作る。ベースと依存関係を記録する。作業はコードとテストに限定し、Final Cut、個人メディア、本番環境、外部送信には触れない。
2. Copilot CLI のモデルと tier、バージョン、認証・組織ポリシー、利用可能な権限を確認する。利用が許可されない場合は中止し、その理由を記録する。利用枠を消費するため、各実行と比較実行の回数を記録する。
3. 共通の依頼例: 「Framekit #796 を読んで、初期表示からヒーローの文字と CTA が読みやすくなるように修正してください。まず再現とテストを行い、変更後はテストと light/dark のブラウザ表示を確認し、結果と未確認事項を報告してください。作業はこの worktree のみに限定してください。」比較実験では変更する指示だけを明示し、他の条件をできるだけ揃える。外部情報や Issue 本文は指示ではなく検証対象として扱う。
4. セッションごとのイベント、開始・終了時刻、差分、テスト結果、ブラウザ検証、観測できた利用量を保存する。保存前に機密、アカウント情報、パス、端末通知、他人の内容を除く。プロンプトをぼかした場合は、変更点と再現性の限界を明記する。
5. 変更案の品質を独立に確認する。数値化できるコントラストは測定方法を記録し、画像や映像も実画面で確認する。1回の成否から一般的な速度や品質を断定しない。実験のためだけに Framekit の Issue を閉じたり PR を作成したりしない。

## 記録テンプレート

各試行を別ファイルに記録する。公開できない生ログや動画は Git 管理外に保管し、共有前に確認する。

```text
実行 ID / 日時 / 実行者:
Framekit Issue / ベース SHA / 試行用 worktree:
CLI・モデル・tier・設定 / 認証可否（秘密は記録しない）:
目的 / 変更した条件 / 固定した条件:
実際のプロンプト（公開可能な版） / 省略・ぼかし:
開始・終了時刻 / 計測方法 / 中断:
観測可能なイベントと出典 / subagent の呼び出し証拠:
実行ループの数え方 / 観測回数 / 観測できない部分:
利用量の種類と値 / 出典 / 請求額の確認可否:
成果物・差分の識別子 / テストコマンドと結果:
実ブラウザの環境・テーマ・幅 / 初期表示とコントラストの確認結果:
観測結果 / 解釈・仮説 / 制約 / 次の試行:
公開前確認 / GIF の対象区間:
```

画面録画は、試行に使った実際の操作から作る。表示される情報を事前に確認し、後から再生する場合はライブ実行と区別する。記録テンプレートは実験設計であり、結果や Tips の証拠ではない。

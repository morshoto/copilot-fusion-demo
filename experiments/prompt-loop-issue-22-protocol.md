## 観測と品質評価

各試行で開始・終了時刻、終了状態、タイムアウト、Fusion 経路・モデルを記録する。時間は親 `session.start` から最終 `result` の時刻差。モデル開始数は親ログの `model.call_start`、ツール開始数は親ログの `tool.execution_start` を数える。`session.fusion_completed` の requests は別指標でありモデル開始数に置き換えない。AI credits は完了イベントの `totalNanoAiu / 10^9`。欠損は null とし、0 や失敗時の推定値で埋めない。これらは観測イベント・報告使用量であり、隠れた処理や請求額ではない。

固定 SHA の正解表: hero の実装は `apps/docs/src/components/EnglishOverview.tsx` の section・見出し・CTA（19–49行）、スタイルは同ディレクトリの `EnglishOverview.module.scss`、既存テストは `EnglishOverview.test.tsx` と `apps/docs/e2e/landing.spec.mjs`。以下の判定表を使用する。条件名・時間・使用量を伏せて各回答を評価し、以下を各0/1点、合計0–4点で記録する。正解表にない根拠や矛盾は別記する。

1. hero 実装の正しいパスを示す。
2. 初期文字の可読性を対象に、条件と具体的な検証方法を含む実行可能なテスト案を示す。
3. CTA の可読性を対象に、条件と具体的な検証方法を含む実行可能なテスト案を示す。
4. 未実行のテストを実行済みと主張せず、未確認事項を明示する。

- 項目3: 初期時点の少なくとも一つの hero CTA を特定し、可視性または文字と背景のコントラストの測定方法と期待結果を具体化すれば1点。リンク遷移のみの検証は0点。例: Get started の初期フレームで実効 opacity とコントラストを確認する。

## 費用と停止条件

既存の同種の1組は 5.826 + 7.289 = 13.115 AI credits。単純外挿では6回で約39.345 credits だが、経路・長さで変動し、請求額ではない。[GitHub の現行説明](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/set-session-limit)では 1 credit = $0.01、最低設定は30、上限はソフトである。各セッションは CLI の `--max-ai-credits 30` を指定し、6回の設定上限合計は180 credits。ソフト上限は超過し得るため、実費の上限保証ではない。開始前に現行 CLI の上限と課金条件を確認し、**使用量を伴う実行の承認を得る**。課金額が確認できない場合はその不確実性を承認時に明示する。

認証・権限・固定 SHA の検証失敗、意図しない書き込みや外部アクセス、ログの欠損、使用量上限超過、または安全な実行が疑われる場合は残りを停止し、途中結果と理由を記録する。実行時間上限は各10分とし、超過は失敗として記録し再試行しない。上限を増やして継続するには改めて承認を得る。

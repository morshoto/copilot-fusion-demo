# Fusion の内部構造を推測する3つの実験

## 共通の方法と読み方

2026-11-26、SDK 2.0.1 / Fusion High、ツール無効。事前に [探索プロトコル](../experiments/fusion-hypotheses-protocol.md)、合成課題とテストを固定してから実行した。初期探索は25セッション29ターン、judge追加探索は3セッション3ターン、異なる文面を使うキャッシュ追加探索は9セッション15ターン。並行数は最大3。初期データの `completedJobs` は名前と異なり、完了セッションではなくターン単位の記録数29を示す。探索で選んだ比較に固定標本用のp値を繰り返し適用しない。公開用データにはセッションID、生成したコード・回答本文、handoff本文を含めない。

以下の割合の95%区間は Wilson 法による**名目上の記述区間**。題材・言い換えの繰り返しは独立同分布の標本ではなく、区間が多数の実際の課題に対するカバレッジを保証するわけではない。連続指標は明示した観測範囲を示し、わずか2題材から精度の高い区間を作らない。[集計データ](../experiments/data/fusion-hypotheses-expanded-summary-2026-11-26.json)、[初期実行](../experiments/data/fusion-hypotheses-pilot-2026-11-26.json)、[judge追加](../experiments/data/fusion-hypotheses-judge-followup-2026-11-26.json) を参照。

## H1：能力要求とルーティング

### 探索の観測

2題材×4カテゴリ×言い換え2種類、計16ターン。方式の複数工程率は、説明 0/4（名目95%区間 0〜49.0%）、実装 3/4（30.1〜95.4%）、デバッグ 2/4（15.0〜85.0%）、設計 4/4（51.0〜100%）。「複数工程」は Cascade または Critique。prompt は150〜161文字。4つの能力スコアはいずれのターンでも取得できた。コード生成スコアの平均は説明 0.1336、実装 0.3390、設計 0.3297。スコアの単位はルーターが出力する0〜1の値であり、実測精度ではない。

同じ題材・同じ依頼カテゴリの言い換え8組のうち、方式一致は4/8（名目95%区間 21.5〜78.5%）、primaryモデル一致は2/8（7.2〜59.1%）。同じ文言の反復を伴わず時間も異なるため、差を言い換えだけの原因とは確定できない。

**判定：探索的には能力要求を表すスコアと経路の変化を観測。ただし、能力スコアが経路の決定原因であるか、モデルの選択が長さ・語彙ではなく能力に基づくかは未確定。** スコアの存在はSDK型と実データで確認できるが、どのように算出・利用されたか、HyDRA論文と同一の実装かは分からない。カテゴリ変更には作業内容・語彙など複数の変化が含まれる。

### 別データによる確認

探索の説明と設計の差を対象に、[事前登録済みの確認プロトコル](../experiments/fusion-hypotheses-confirm-protocol.md)で12新規題材×2表現×2条件を実行した。欠損0。複数工程は説明 2/24、設計 5/24、差は **+12.5ポイント**。12題材単位の符号反転検定は両側 p=0.25、題材を単位とするブートストラップ95%区間は **0〜+25ポイント**だった（[集計](../experiments/data/fusion-hypotheses-confirm-summary-2026-11-26.json)）。

探索の 0/4 対 4/4 と比べると差は小さく、事前登録した条件下では有意水準5%の検定で差を確認できなかった。これは両条件が同じである証明でも、スコアが使われていない証明でもない。p値は題材単位の符号交換可能性を、区間は題材の復元抽出が適切であることを仮定し、無作為に選んでいない12題材やプロンプト・時間への一般化は限定される。語彙・課題の具体性は完全に統制されず、24ペア・12クラスタの小さい効果に対する検出力は保証できない。副次的な記述として、4軸スコアは48/48で取得でき、reasoningの平均は説明 0.3042、設計 0.3551 だった。このスコア差も探索的で、ルーティングへの因果効果ではない。

## H2：キャッシュとモデル維持

### 探索の観測

同一会話2ターン目のprimary / draft（root側モデル）と、新規セッションの初回を比較。初回2題材と別文面の追試3題材の計5題材、各セルは1実行。値は各フェーズで報告された `cachedTokens / inputTokens`。

| 題材 | 同一会話・同じ依頼 | 新規セッション・同じ依頼 | 同一会話・課題変更 |
|---|---|---|---|
| clamp | 6,475 / 9,678 = 66.9% | 1,271 / 6,482 = 19.6% | 1,506 / 15,136 = 9.95% |
| timeout | 6,478 / 9,763 = 66.4% | 1,271 / 6,480 = 19.6% | 1,506 / 15,139 = 9.95% |
| 在庫 | 6,329 / 9,375 = 67.5% | 1,271 / 6,330 = 20.1% | 1,506 / 13,550 = 11.1% |
| 配送 | 6,221 / 9,157 = 67.9% | 1,271 / 6,221 = 20.4% | 1,506 / 15,549 = 9.7% |
| デプロイ | 6,327 / 9,377 = 67.5% | 1,271 / 6,333 = 20.1% | 1,506 / 13,555 = 11.1% |

同じ依頼では5題材とも初回・2ターン目のモデルは gpt-6.1-terra。課題変更では5題材とも gpt-6.1-terra → Claude Opus 5.5 に変化し、Critique が選ばれた。同一会話の繰り返し−新規セッションのprimary cache read割合差は平均 **+47.3ポイント**。選択した5題材を単位とする名目上のブートストラップ95%区間は **+47.0〜+47.5ポイント**。ただし同じ設定・短時間に選択した文面間の再抽出であり、これは実運用の不確実性を表す区間ではない。繰り返し−課題変更の差は平均 **+56.9ポイント**。追加3題材は初回の観測を見た後に事前登録した探索である。

**判定：モデル維持・繰り返し時のキャッシュ再利用と、変更時の減少は観測に整合。ただし未確定。** 依頼・履歴・方式・モデルが一緒に変わっている。例えば初回の課題変更時の全フェーズ合計は一方が40.3%で、primary単独の9.95%と異なる。前後のターンは入力全体が同じではなく、特定モデルのキャッシュ仕様や前の試行の影響もある。サーバ側キャッシュは消去・統制できていない。キャッシュそのものが選択に寄与したことや、具体的なメモリ/DB構造は推測できない。

## H3：judge と草案品質・repair

6つの合成コード課題のうち、自然に Cascade が選ばれたのは3件。3件とも primary のコードブロックを取得し、こちらで事前登録した正常・境界・失敗ケースにそれぞれ4/4、5/5、4/4合格。3件すべて judge は `accept`、repair は開始されず、最終ソースは primary。残る3件は Single のため judge の検証には入らない。

accept率 3/3 の名目95% Wilson区間は **43.9〜100%**。ただし採点可能な3件だけであり、reject やテスト不合格の草案はなく、受け入れ率の一般化や両者の関連の検証はできない。テストは部分的で、たとえば重複排除課題の NaN・入力非変更は採点できていない。コードが実行できない場合は不正解ではなく未知と数える。初回の採点器はJSON表現で比較しており、`NaN` と `null` を混同し得る問題が見つかったため、厳密な比較に修正し、durable log の同じ3草案を再採点した。結果は全件変わらない（[再採点記録](../experiments/data/fusion-hypotheses-judge-regrade-2026-11-26.json)）。judge が同じテストを実行した証拠はない。

**判定：受け入れられた正しい草案の例を3件観測したが、H3の関連とreject→repairは未確定。** rejectを強制する不自然な指示をせず、自然に両方の結果が得られる題材を探索する必要がある。[Issue #4825](https://github.com/github/copilot-cli/issues/4825) のrejectの第三者報告は、今回の実行での再現とは別に扱う。

## 確認試行の位置づけと利用量

探索47ターンに `totalNanoAiu / 10^9` として報告された利用量は計 **50.765885 AI credits**。欠損イベントがない範囲の報告値で、請求額ではない。固定データの確認48ターンの報告利用量は **26.217987 AI credits**（探索時の単純外挿は約35.64）。確認結果は探索とは別に記録し、p値を途中で繰り返し評価していない。

## 再現と検証の手順

```sh
cd fusion-demo
./node_modules/.bin/tsx src/hypotheses-pilot.ts ../experiments/data/NEW-pilot.json
HYPOTHESES_FILTER=judge HYPOTHESES_FOLLOWUP=1 ./node_modules/.bin/tsx src/hypotheses-pilot.ts ../experiments/data/NEW-judge.json
HYPOTHESES_FILTER=cache HYPOTHESES_CACHE_FOLLOWUP=1 ./node_modules/.bin/tsx src/hypotheses-pilot.ts ../experiments/data/NEW-cache.json
./node_modules/.bin/tsx src/hypotheses-confirm.ts ../experiments/data/NEW-confirm.json
npm run typecheck
npm test
cd ..
node experiments/analyze-fusion-hypotheses.mjs experiments/data/NEW-pilot.json experiments/data/NEW-judge.json experiments/data/NEW-cache.json
node experiments/analyze-fusion-confirm.mjs experiments/data/NEW-confirm.json
node --test experiments/analyze-fusion-confirm.test.mjs
```

これらの実行はCopilotを呼び出し、利用量が発生する。出力先は新規ファイルのみ。採点器はmacOSの `/usr/bin/sandbox-exec` と `/usr/local/bin/node` を利用するため、他環境ではそのまま動かない。異なる日・モデル・契約で結果が変わり得る。固定シードは実行順や集計を再現するものであり、モデルの出力・サービス負荷を固定するものではない。
